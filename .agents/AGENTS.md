# oTalk_app 개발 규칙

이 파일은 `c:\otalk_app` 워크스페이스에서 작업할 때 **항상 자동으로 적용**되는 규칙입니다.
사용자가 매번 언급하지 않아도 아래 모든 규칙을 준수하여 작업을 수행하세요.

---

## 1. 항상 적용할 개발 주의사항

### 코드 수정 원칙
- **기존 기능 보호**: 수정 사항이 기존 기능을 깨트리지 않는지 항상 확인할 것.
- **Shorebird 원격 패치 방어(에셋 보호) 규칙**: Dart 로직 수정(원격 패치 배포)만이 목적인 경우, 불필요하게 `Icon(...)` 위젯의 종류를 변경/추가/삭제하지 않도록 극도로 주의할 것. 아이콘 사용 내역이 달라지면 `MaterialIcons-Regular.otf` 파일 트리쉐이킹 결과가 달라져 에셋 변경으로 간주되고 패치가 불가능해집니다. 어쩔 수 없이 건드리는 게 아니라면, UI 수정 시 아이콘을 함부로 바꾸지 마세요.
- **Opacity/오버레이 주의**: `Scaffold` 전체를 `Opacity`, `Stack`, 또는 다른 투명도 위젯으로 감싸면 터치 이벤트가 막히거나 배경 블러 버그가 발생할 수 있으므로 금지. 반투명 배경이 필요할 경우 `backgroundColor: Color(0xCC000000)` 방식으로 처리할 것.
- **최소 범위 수정 원칙**: 요청된 내용 외의 코드는 건드리지 말 것.
- **디자인 원칙**: 검정 바탕에 노란색 포인트를 활용한 세련되고 직관적인 UI(Black & Yellow Premium Theme)를 유지할 것.
- **위젯 분리**: 유지보수를 위해 하나의 파일에 모든 코드를 넣지 말고, 재사용 가능한 위젯 단위로 철저히 쪼개서 `lib/widgets` 하위에 배치할 것.

### 커밋·푸시 규칙
- 작업 완료 후 반드시 `git add` → `git commit` → `git push origin main` 순서로 수행. (단, 로컬 단계일 때는 커밋만 준수)
- **커밋 메시지는 한글로 상세하게** 작성. 아래 형식 준수:
  ```
  [태그] 제목 요약

  1. 변경 항목 상세 설명
  2. 변경 이유 및 근거
  3. 주의사항 또는 영향 범위
  ```
- 태그 종류: `[fix]`, `[feat]`, `[refactor]`, `[원복]`, `[chore]`, `[perf]`
